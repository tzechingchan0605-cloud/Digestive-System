# 未知消化液虛擬實驗室（VL1）

繁體中文的四階段 IBL：了解情境 → 設計探究 → 四組基本實驗及兩組熱處理 → 結論、學習重點及反思。使用 HTML、CSS、JavaScript，無需建置。學生不需 Google 登入；跨裝置收集使用 Google 試算表及 Apps Script 後端。

## 啟動

```bash
cd /workspace/Digestive-System
python3 -m http.server 8000 --bind 127.0.0.1
```

使用瀏覽器開啟該靜態伺服器。Google Fonts 可選，無網路時使用系統字型。本機儲存始終保留；設定雲端後，答案及裝置圖會同步至集中紀錄。

## 學生與紀錄

輸入姓名、班別及學號、電郵後，每次登入均開始全新探究，包括同一電郵再次登入。開始第一次實驗前保存原始設計快照；首次確認的觀察、最後答案及操作事件分開保留。原始預測不因與結果不符而自動判錯。設計區依 01–05 分成五張卡片，繪圖／相片區在文字設計之前；確認基本觀察後自動捲至數據表。推論區保留三題，熱處理另有延伸結論。前提及客觀題選項每次新探究重新排列，同一次探究保持固定；順序作為 optionOrder 保存在紀錄中，評分按答案內容。

探究提交後，原探究答案鎖定，學習重點及反思欄開放。學習重點及 PDF 另有乳化與脂質水解的結構示意圖：乳化前後分子不變，水解以三酸甘油酯＋3H₂O→甘油＋3個脂肪酸的完全水解簡化模型呈現。提交非空白反思後反思鎖定，才可列印／儲存 PDF。PDF 不含能力或知識分數，也不再顯示最後保存的假說及理由；原始假說與理由保留。列印標題預設為 `VL1_未知消化液X與Y_[班別及學號]_[姓名]`，禁用字元會替換；實際儲存檔名仍由瀏覽器列印介面決定。

重新整理／離開會觸發瀏覽器原生確認（提示內容由瀏覽器決定，亦受瀏覽器的使用者互動政策限制）。取消保留原探究；接受後重新整理返回空白登入。按「開始新探究」只確認一次，保留舊紀錄。切換帳戶會先保存原學生，清空作答、繪圖、動畫及計時。

有效用時只計登入後頁面可見的探究時間，排除背景及登入表單時間；事件保留實際 UTC 時間戳，報告時間以香港時區顯示。舊版用時保持原值並標示，不能追溯轉換成新計時。

## 教師

輸入指定教師電郵 `tzechingchan0605@gmail.com` 開啟教師儀表板。設定雲端後須再輸入教師雲端密碼，才能讀取全班紀錄。可查看每份學生唯讀報告、列印該份 PDF 或匯出全班 Excel。「進入示範探究」建立新狀態；教師示範可完成所有階段及反思並列印 PDF，儲存函式及事件函式均排除教師，不會加入學生紀錄或 Excel。頁面頂部按鈕可隨時返回儀表板。

Excel 包含七張工作表：學生探究答案、六組觀察紀錄、教師評分、評分準則、操作事件紀錄、原始與遞交快照、裝置設計圖。客觀作答有綠／紅字，人工評分對應的答案欄在填分後按公式呈綠／橙／紅字，題目類別使用不同底色。原始快照及事件內容超過 Excel 儲存格長度時分段；依識別碼、類別及分段序號串接可還原原文。超長答案欄只顯示有明確提示的摘要；「本機完整紀錄（含舊版原值）」分段保留全文。

六項 SPS 各 4 分（24），反思新知識四項各 2 分（8），整體 32。十個人工欄有整數範圍驗證，總分公式另外檢查範圍；空白為待評，填 0 才是零分。學生完成反思且必要評分完整才顯示整體分數。評分準則是待研究者校準的活動 rubric 初稿，並非已驗證 SPSAI／CKT 量表。人工分數只存在教師保存的 Excel；重新匯出不會讀取之前填分，請另存已評檔案。

## 重要限制與舊版相容

跨裝置收集設定見 [雲端收集設定](cloud/SETUP.md)。`cloud-config.js` 的 `endpoint` 未設定時只使用本機備份，介面會明確提示。Apps Script 第 2 版使用嵌入頁及 Google RPC 連線，避免直接跨來源讀取失敗；舊部署需依設定文件更新至新版本。設定後學生紀錄自動上傳，教師憑指定電郵及額外密碼讀取全班紀錄；匯出 Excel 前會重新載入雲端資料，失敗不下載部分紀錄。舊手機紀錄須在原瀏覽器重新開啟網站補傳；本機儲存已清除的答案不能復原。

網站不會更新電腦上已下載的 Excel；重新下載生成最新全班檔案。人工評分仍只存在教師另存的 Excel。指定電郵本身不是 Google 身分驗證；雲端讀取另有密碼保護，學生電郵仍為自行輸入。

保留原有 `digestiveLab.localRecords.v1` 及 `digestiveLab.v4` 資料；新紀錄按 UUID 更新，不再以電郵＋模組覆蓋。舊版缺少原始快照、反思或新題時顯示「未提供」，不捏造作答。舊版控制變量按原有三項題目顯示回饋，不能用新增五項 rubric 對其自動評分。舊版及未完成紀錄仍可由教師預覽／列印。

## 驗證

測試使用獨立瀏覽器 context 與測試資料，不接觸真實學生資料。一般介面測試會攔截雲端設定並阻止 Google 收集端連線；`cloud.cjs` 使用本機收集端測試替身，不會把測試資料寫入教師的真實試算表。需要 Node.js、Playwright、Chromium、Python 及 openpyxl；環境現有工具已可執行。先啟動上述伺服器，再執行：

```bash
node --check app.js
node --check excel.js
node --check cloud-sync.js
node --check cloud-bridge.js
node tests/cloud_setup.cjs
node tests/cloud.cjs
node tests/smoke.cjs
node tests/edge_cases.cjs
node tests/layout.cjs
node tests/learning.cjs
python3 tests/excel_scores.py
```

`smoke.cjs` 驗證完整學生及教師流程、首次／最後答案、反思/PDF 門檻、切換帳戶、重複電郵、動畫取消、原生重新整理確認、可見時間、舊版相容、Excel 前後一致、手機和圖片上載。產物在 `/tmp/vl1-*.xlsx`、`/tmp/vl1-student.pdf` 及 `/tmp/vl1-mobile.png`。`edge_cases.cjs` 另外驗證舊備份只遷移一次、文字注入防護、未知／損壞資料保留、320px 版面及超長 Unicode 匯出。`layout.cjs` 驗證指定文字、五張編號卡片、刪除選項、繪圖順序、三題 VL2 格式及歷史評分。`learning.cjs` 驗證提示樣式、選項排列／保存、按內容評分、學習圖的顯示門檻、手機可讀性與 PDF 圖像。Python 檢查實際 XLSX 的 XML、底色、文字顏色、圖片、範圍驗證及公式（包括待評、0、超範圍、反思門檻）。公式測試解讀匯出檔的函式子集，不等同人工測試每種 Excel／印表機版本。

跨 VL 比較、rubric 配分及紙本對照組同步題目見 [研究與對照組說明](RESEARCH_ALIGNMENT.md)。
